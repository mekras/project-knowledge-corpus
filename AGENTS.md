Проект является APM-коллекцией навыков для создания, сопровождения и применения
корпуса знаний проекта. Первичные данные являются частью корпуса знаний.
Проект публичный.

## Входной протокол

Перед ответом, вопросом, исполнением или передачей работы по каждому элементу
корневого входа агент открывает `.agents/skills/ait-routing/SKILL.md`.
Если этот путь недоступен, используется `.claude/skills/ait-routing/SKILL.md`.
Агент следует открытому навыку: выбирает режим и первым сообщением показывает
маршрут со строками «Режим менеджера» и «Маршрут». Если оба файла отсутствуют,
агент останавливается и сообщает о блокере.

## Концепция проекта

Концепция проекта находится в начале [`README.md`](README.md), от заголовка до
ссылки «Подробнее…». Перед предметной работой прочитай этот фрагмент и сверяй
с ним результат.

## Граф влияния

Граф влияния проекта находится в [`project-impact.json`](project-impact.json).
После изменения отслеживаемого артефакта применяй `ait-impact-analysis`.

Публикуемые навыки хранятся в `.apm/skills/<name>/`. У каждого навыка должны быть
`SKILL.md`, `agents/openai.yaml` и `evals/triggers.json`.

При добавлении или изменении навыка проверяй коллекцию командой:

```bash
apm run tests
```

## Самоприменение APM

При изменении `.apm/skills/**` вместо прямых `apm install` и `apm audit --ci`
запускай безопасный цикл:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 tools/run-apm-safe.py \
  --audit-runner tools/apm-audit-ci
```

Локальный запускатель сохраняет полный аудит и принимает только подтверждённое
совпадение развёрнутого файла с текущим `.apm`-источником при самоприменении.
Для повторного аудита без установки запускай
`PYTHONDONTWRITEBYTECODE=1 python3 tools/apm-audit-ci`.

Если изменение заметно пользователям или сопровождающим проекта, проверяй
необходимость записи в `CHANGELOG.md` через навык `ait-changelog`.

## Экономное использование подагентов

Применяй `ai-setup-subagents`, если пользователь прямо просит использовать,
настроить или проверить подагентов, если задача требует гарантированного выбора
класса исполнения либо если срок проверки локальной политики истёк.

Конкретные классы, модели, режимы доступа и ограничения хранятся в исключённом
из Git файле `subagents.local.toml`. Не переноси их в `AGENTS.md` или Git без
отдельного решения пользователя.

Для гарантированного выбора класса запускай:

```bash
printf '%s\n' '<задача>' | \
  tools/run-execution-class <класс> --target codex --input <явный-входной-файл>
```

Считай запуск успешным только по записи с совпавшими назначенной и фактической
моделями, непустым `agent_path`, журналом и итогом. После фактического запуска
подагента сообщай использованные модели, расход и время. Родительский агент
проверяет свидетельства и принимает итоговое решение.

## Внесение изменений

- Разрешается вносить изменения только внутри папки проекта.

## Проектные решения

При сравнении вариантов значимого проектного решения учитывай факторы в таком
порядке:

1. Обязательные ограничения и совместимость публичных контрактов.
2. Влияние на пользователей и их рабочие процессы.
3. Риски ошибок, миграций и потери данных.
4. Обратимость решения.

## Git

- Все изменения, даже чужие, если они не исключены через `.gitignore`, сразу
  добавляй в индекс Git.
- Сообщения коммитов оформляй по схеме Pro Git. Русская тема кратко описывает
  завершённый результат, при необходимости добавляй поясняющее тело. Перед
  коммитом применяй `ait-commit-messages`.
- Не делай commit и push без явной просьбы пользователя.
