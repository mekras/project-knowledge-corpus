# Как настроить допуск материалов в корпус

Запустите `kc-setup` и назовите границы корпуса. Например:

```text
Настрой корпус знаний проекта. Рабочие разговоры с агентом не включать.
Решения сохранять в docs/decisions. Документацию example.org/reference можно
добавлять без отдельного вопроса. Остальные новые источники согласовывать.
```

Навык проверит существующие правила, подготовит договор допуска через
`kc-inventory`, обновит инструкции агента и подключит проектную проверку.
Он сохранит более строгие местные ограничения и сгруппирует вопросы, которые
нельзя решить по уже принятой политике. Одно разрешающее правило избавляет от
повторных вопросов для каждого подходящего документа.

Допуск в корпус, использование решения при разработке и разрешение публикации
проверяются отдельно. Подтверждение требования позволяет записать решение и
обновить проектные документы. Оно не разрешает сохранять диалог как первичный
источник. Для понятия, введённого решением, предусмотрена ссылка на принятую
запись вне корпуса. Определение остаётся в понятийном аппарате.

Если корпус уже существует, сначала разберите происхождение и основания
допуска его источников. Успешная прежняя проверка структуры и `approved` в
карточке не подтверждают разрешение. Включение нового договора может выявить
неразрешённые случаи. Данные автоматически не удаляются.

Точные поля политики, происхождения и записей решений, команды проверки и
ограничения автоматизации описаны в
[договоре допуска материалов](../../.apm/skills/kc-inventory/references/source-admission.md).
Проверка обнаруживает несоответствие записанному договору. Правдивость
происхождения и принятие решения человеком требуют содержательной приёмки.
