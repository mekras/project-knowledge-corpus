# Как работать с источником с ограниченным доступом

Источник с локальной авторизацией можно использовать без переноса секретов и
без потери уже выполненной проверки снимка. Карточка хранит постоянные
требования, локальное окружение — профиль и сессию, а корпус — снимок и
проверочное основание.

## Добавьте источник

Попросите агента добавить ссылку через `kc-sources-add`. В карточке должны
появиться:

- переносимый локатор и проектный `adapter`;
- вид авторизации и необходимые возможности;
- логическое имя профиля без секрета;
- стратегия хранения и политика копирования;
- условия конкретного действия со статусом `permitted`, `restricted`,
  `unknown` или `prohibited`.

Неизвестные условия сохраняйте как `unknown`. Это не разрешение на получение,
хранение или публикацию.

## Зарегистрируйте проектный адаптер

Коллекция не поставляет адаптер для конкретного закрытого сервиса. Проект может
хранить свой адаптер рядом с проектом или корпусом и зарегистрировать его в
локальных настройках операций по договору версии 2. Адаптер объявляет:

- `probe` для проверки готовности;
- `fetch` для получения конкретного материала;
- `verify` для сопоставления снимка с источником;
- необязательную `authorize` для явной интерактивной настройки.

`authorize` не запускается полным проходом автоматически.

## Настройте локальный профиль

Храните профиль в игнорируемом слое, например `.local/access-profiles.yml`, или
в защищённом хранилище проекта. В отслеживаемой карточке остаётся только
логическое имя. Не передавайте токены, cookies, пароли и данные сессии через
аргументы команды, стандартный вывод или отчёт.

Проверьте готовность без изменения корпуса:

```bash
python3 .apm/skills/kc-pipeline/scripts/run-corpus-operations.py \
  knowledge --operations knowledge/operations.yml --run-adapters \
  --adapter-operation probe --source SOURCE-ID
```

Результат различает готовность, отсутствующий профиль, необходимость входа,
недостаток полномочий, неизвестность условий и техническую недоступность.

## Получите снимок

После успешного `probe` запустите `fetch`. Адаптер сохраняет материал только в
разрешённой области. Для снимка вычисляется SHA-256. Новый хэш требует новой
проверки происхождения.

```bash
python3 .apm/skills/kc-pipeline/scripts/run-corpus-operations.py \
  knowledge --operations knowledge/operations.yml --run-adapters \
  --adapter-operation fetch --source SOURCE-ID
```

## Зафиксируйте проверку при получении

Если при получении проверены оригинал, дата и охват снимка, запишите
`acquisition_check` и сохранённое свидетельство. Повторная загрузка не нужна.
Свидетельство должно описывать фактическую проверку, а не только название
адаптера. Метаданные подтверждаются лишь в явно проверенной области.

```bash
python3 .apm/skills/kc-inventory/scripts/record-snapshot-verification.py \
  knowledge/data/source/pages/item \
  knowledge/data/source/pages/item/message.md \
  --acquisition-method adapter_fetch \
  --verification-method acquisition_check \
  --evidence "Запись получения: оригинал установлен, полный текст сохранён 2026-10-09." \
  --acquired-at 2026-10-09 --checked-at 2026-10-09 \
  --content-scope full_text --content-match verified \
  --scope-completeness complete --overall-result verified \
  --checked-by-role corpus_maintainer
```

Команда записывает заявленную проверку и её хэш. Она сама не получает
источник и не доказывает истинность свидетельства. Для старой единицы без
свидетельства происхождение остаётся неизвестным, но это не требует
массового повторного получения ради использования сохранённого текста.

## Если прямого доступа нет

Пользователь может положить текст или файл в папку единицы. Запишите способ
получения `user_provided`. Материал можно нормализовать, извлекать из него
утверждения и проверять точность этих утверждений относительно текста. Снимок
при этом остаётся `unverified` относительно внешнего источника.

Это различает два утверждения: «в предоставленном сообщении сказано X» и «X —
действующая норма». Второе требует отдельной проверки актуальности.

## Запишите ручную сверку

Для одной единицы используйте средство записи проверки. Оно проверит, что
артефакт находится внутри единицы, вычислит хэш и мигрирует только эту единицу
на договор версии 2.

```bash
python3 .apm/skills/kc-inventory/scripts/record-snapshot-verification.py \
  knowledge/data/source/pages/item \
  knowledge/data/source/pages/item/message.md \
  --acquisition-method user_provided \
  --verification-method manual_confirmation \
  --content-scope full_text \
  --content-match verified \
  --scope-completeness complete \
  --overall-result verified \
  --checked-by-role corpus_maintainer
```

Для фрагмента выберите `--content-scope fragment` и передайте точный
`--fragment`. Локатор, автор и дата подтверждаются только отдельными
`--metadata` и `--metadata-result`. Совпадение текста не подтверждает права на
использование.

## Перенесите корпус в другое окружение

`verification.yml` хранится в переносимом слое и связан с хэшем. Если другое
окружение не имеет профиля, оно всё равно может проверить локальную целостность
и использовать прежний результат. Новая прямая сверка и проверка актуальности
откладываются до появления доступа.

## Повторно проверьте актуальность

Актуальность источника и утверждений не следует из даты `probe` или совпадения
снимка. Для исторического материала достаточно проверки на дату получения.
Повторную сверку назначайте при новом снимке, признаках ошибки получения,
недостаточном происхождении, отдельном запросе или по политике обновления.
Когда по этой потребности наступил `next_check_at` или правило обновления,
запустите `verify`. Прежнее основание исторического снимка сохраняется.
Если источник изменился, получите новый снимок, вычислите
новый хэш и запишите новую проверку.

## Исправьте ошибочное подтверждение

Снова запустите средство записи для той же единицы с правильным способом,
областью, результатом и ограничениями. Команда безопасно заменит
`verification.yml` текущего снимка. Не редактируйте старый результат так, чтобы
он применялся к другому хэшу. Если проекту нужна аудиторская история, включите
её отдельной политикой до сохранения прежних записей.
